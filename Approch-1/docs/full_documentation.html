1. Executive Summary

Objective: Determine whether a medical insurance claim is Legitimate (0) or Fraud (1) using only the existing 4,500-row Excel dataset provided in the repository. This documentation is part of a larger three-approach project (Approach 1 = ML, Approach 2 = Deep Learning, Approach 3 = Indicator-Based System). This document covers only Approach 1 and the integrated full-stack website, as requested.

The dataset contains 4,500 claims with 19 original fields (after expansion of date features = 14 model inputs). There is no missing data, no duplicates, and no synthetic records have been added. The target variable ClaimLegitimacy is imbalanced: 4,230 Legitimate (94.0%) and 270 Fraud (6.0%), reflecting real-world fraud ratios.

4.3 Evaluation Metrics

Because fraud is the minority class, accuracy alone is misleading. We report:

  • Precision — of predicted fraud, how many are actual fraud (minimize false alarms)
  • Recall (Sensitivity) — of actual fraud, how many are caught (minimize missed cases)
  • F1 — harmonic mean of precision and recall — primary comparison metric
  • ROC-AUC — ranking performance across thresholds
  • PR-AUC (Average Precision) — more informative than ROC for imbalanced data

5.2 Best Model

Best by Validation F1: GradientBoosting (F1 = 1.000 on validation; 0.987 on test).

Best by Test F1 (tie): RandomForest, XGBoost, and GradientBoosting all achieve ~0.987–0.988 F1, indicating that tree-based ensemble methods dominate this structured dataset. Logistic Regression remains a strong, interpretable baseline (F1 = 0.769), while SVM provides a reliable middle ground.

Caution — Very High Performance: The near-perfect ROC-AUC values (0.99–1.00) across all tree-based models suggest that the dataset contains strong predictive signals—likely the Cluster feature and claim-type/status combinations—which may reflect synthetic-like patterns in the original Excel file rather than pure noise. For production deployment (Approach 2 / 3 upgrade), external validation on a truly held-out temporal cohort (e.g., post-2024 claims) is strongly recommended.

9. Limitations & Next Steps (Industry Best Practice)

  1. Temporal Validation: All splits are random. A true fraud-detection pipeline should validate on future time periods (e.g., train on 2022–2023, test on 2024) to avoid lookahead bias.
  2. Class Imbalance Handling: While class_weight balances training, operational thresholds should be tuned for business cost (cost of false positive vs. missed fraud).
  3. Code Aggregation: The high-cardinality diagnosis/procedure codes were dropped. For deeper clinical modeling, grouping into CCS/DRG categories and adding comorbidity indices (Charlson) would improve generalizability.
  4. Approach 2 (Deep Learning): A feed-forward neural network with embedding layers for categorical features could capture non-linear interactions not fully represented by tree splits. This is planned for upgrade.
  5. Approach 3 (Indicator-Based): A rules engine combining provider billing patterns, claim-time anomalies, and historical denial rates would complement ML with explainable heuristics.
